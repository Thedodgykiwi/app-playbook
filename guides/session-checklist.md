# Session checklist (read first, every session)

Every session on an app follows this, **including quick fixes**. Kept short
on purpose (it's read every session); details are in the linked guides.
Why: a quick-fix session skipped the rules and invented its own issue format
(Edit 1 Job Board #25).

## 1. Start

- [ ] App repo **and** this playbook attached; read the app's `CLAUDE.md`
      and brief (`docs/brief.md`). No brief: new app → kickoff
      (`new-app-kickoff.md`) before feature work; existing app → offer one.
- [ ] `git checkout dev && git pull`. Work only on `dev`.
- [ ] **Catch up, sized to the request:**
      - *Pure question* → none.
      - *Quick fix* → one line: last deploy OK? anything parked on this?
      - *Real work / first session in a while* → 3–5 plain lines: recent
        commits and open issues (high priority first); stages
        (`promote.sh status`); last deploy (`actions_list`; failed → say so
        first); parked work (`wip/*` branches, "Where I got to" comments: pick
        up from there); next must-have in the brief; app behind the starter
        (`docs/starter-version.md`) → mention once (`upgrading-an-app.md`).

## 2. Every request, however small

- [ ] **Choice card first** (AskUserQuestion): "Log it, build later" /
      "Log it + mock-up first" / "Build it now", recommended first. Skip if
      the user already said which, or it's a question.
- [ ] **Issue before any code**, label `bug` / `feature` / `tweak` /
      `performance`, exactly this layout (`issues.md`); the problem, not the
      code fix:

      **What's happening / what's wanted**
      <one or two plain sentences>

      **Where**
      <stage and place, e.g. "All stages, Job Queue cards"; device if known>

      **Expected**
      <what it should do or look like>

      **Reported by**
      <role: "us", "tester", "client"; never a name or email>

      **Notes**
      <optional: screenshots, links, history>

      ---
      _Generated by [Claude Code](https://claude.ai/code)_

- [ ] Screenshot from the user → `docs/issue-images/` on `dev`, shown in the
      issue. Bug caused by another issue's change → its **sub-issue**.
- [ ] Changes or conflicts with the brief → say so; with the user's OK,
      update the brief and its change log (`new-app-kickoff.md` §5).
- [ ] Visible change with more than one sensible design → mock-up first, as
      a **clickable Claude artifact built from the real app** with realistic
      data, options side by side; not static pictures
      (`working-with-the-user.md`).

## 3. Build

- [ ] Small change on `dev`; one issue per commit, ending `Issue #<n>`
      (not "Fixes").
- [ ] Checks pass: `node /home/user/app-playbook/tools/check-app.js --pages
      "<screens>"` plus the app's own (its `CLAUDE.md` "Checks"). Look at the
      change at phone and desktop, light and dark; measure alignment
      (`design.md`).
- [ ] No secrets, emails or personal data in the repo or issues.

## 4. Finish

- [ ] **Saving:** small fix → push once to `dev`. Several steps → push each
      working step to `wip/<issue>-<short-name>` (no deploy), merge to `dev`
      when done. Why: sessions can stop without warning; only pushed work
      survives. Push rejected → fetch, read, combine, re-check; never
      force-push (`stages-and-releases.md`).
- [ ] **Parking** (user sets it aside, however they say it, or the session
      can't finish): push what's done, comment **"Where I got to:"** (done, not
      done, next step, branch) on the issue, confirm in one line.
- [ ] Deploy succeeded and `check-app.js --url <Dev link>` passes.
- [ ] Tell the user what changed and what was / wasn't tested, plainly,
      ending: `You can see it in action here: <Dev link>`.
- [ ] Must-have released to Production → tick it in the brief.
- [ ] Lesson for **any** app → the playbook (generic, to `main`, one line to
      the user); fact about this app → its `CLAUDE.md` (playbook `CLAUDE.md`).
- [ ] Promote only when asked (`promote` skill), with a "what to try" list;
      Production needs an explicit "yes" (`testing-and-testers.md`).
